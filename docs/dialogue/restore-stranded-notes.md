### Findings

1. **blocker — A4 will not clear an already-saved notice merely by moving the log and relaunching.**
   Evidence: `Sources/UnliRice/AppStore+Notices.swift:94-102` posts current findings but returns immediately when there are none. It never removes old findings. `Sources/UnliRiceCore/Notify/NoticeStore.swift:29-30,49-68,128-141` saves notices in `notices.json`; posting refreshes an unread matching notice, rather than reconciling the list with current health. Marking read retains the entry (`:71-85`). Only Clear removes it (`:88-93`; UI action at `Sources/UnliRice/AppStore+Notices.swift:73-75`). Moving the predecessor makes that path cease producing a finding (`Sources/UnliRiceCore/CorpusHealth.swift:52-59`), but the historical notice remains. Another predecessor with missing IDs can still produce a new notice.
   Change to the plan: distinguish “no new stranded-corpus finding” from “historical notice removed.” Replace A4's relaunch-only acceptance with a check of both predecessor paths and an explicit founder choice about clearing the saved notice list through the existing UI (which clears all notices). If selective automatic removal is required, return to the planner: that is a code change outside this repair. Do not edit `notices.json` as an improvised repair.

2. **should-fix — A2 has no safe restart procedure after a partial or ambiguous failure.**
   Evidence: `Sources/UnliRiceCore/NoteService.swift:107-110` allocates a fresh UUID every time, appends, then reads the note back. `Sources/unlirice-mcp/ToolDispatcher.swift:57-79` handles creation and tagging as separate calls; there is no six-note transaction or idempotency key. Three successful creations followed by an error leave three permanent notes, potentially with incomplete tags. Even a failed response can follow a successful append. Repeating the whole step can create duplicate permanent titles. A1's initial clash check does not say how to resume.
   Change to the plan: persist a per-note record of original ID, target title, expected body, returned new ID and completed tags immediately after each call. On any error stop before A3/A4. Before retrying an uncertain creation, search including archived notes, match title case-insensitively, and inspect body/provenance/history. Resume tagging an identified successful note; create only a confirmed missing note. If identity or content differs, stop for the planner rather than correcting, merging or archiving it. Check whether the dated index block already exists before retrying A3. Rollback means stopping with a recorded partial restore and the old log intact, never overwriting the live log from a backup.

5. **should-fix — A4 needs a check for old-path users and a no-overwrite recovery condition.**

### What I checked and found fine

- **Title resolution:** oldest creation timestamp wins, with UUID string breaking ties (`Sources/UnliRiceCore/Projector.swift:161-166`); LinkIndex uses the same rule (`LinkIndex.swift:73-87`). Replaying the original July index could therefore displace the newer live index. A D2 recreation today would instead lose to an older incumbent; excluding clashes is still correct. Matching lowercases titles, trims whitespace inside link brackets, and supports UUID targets; it does not strip punctuation or collapse internal title whitespace (`WikiLink.swift:19-38`, `Projector.swift:173-179`). Six targeted searches including archived notes found no case-insensitive exact title collisions on 2026-11-08. A1 should explicitly include archived notes and repeat immediately before writes.
- **Connector text:** the dispatcher requires non-empty strings and passes them through (`Sources/unlirice-mcp/ToolDispatcher.swift:57-62,180-184`). It neither rewrites wiki links nor invents source attribution. Creation has no tags argument (`ToolCatalog.swift:33-39`); separate tag calls are needed. Source is supplied by the executor: Claude can write as `claude`; Codex must write as `codex` under AGENTS.md. The six reconstructed bodies range from 710 to 4,373 characters before provenance, comfortably below the native encoded-line limit of 1 MiB (`Sources/UnliRiceCore/EventStore.swift:59,144-148`). Empty titles become Untitled during projection (`Projector.swift:74`); these titles are non-empty.
- **Reconstruction:** appends include the exact `\n\n---\n` separator when a body is non-empty (`Sources/UnliRiceCore/Projector.swift:82-85`). A1 must reproduce that separator rather than simply concatenate texts. The five wiki bodies contain 20/6/4/4/11 link occurrences respectively; Corpus reset contains four.
- **Automation boundary:** creation dispatch has no inline janitor/autopilot call. Exact original tags can be checked immediately; subsequent extra machine tags need not mean corruption. Ingest is limited to notes it created (`Sources/UnliRiceCore/Ingest/IngestRunner.swift`, confirmed against its existing-note selection).
