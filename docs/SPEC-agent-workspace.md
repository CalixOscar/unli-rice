# SPEC — Agent workspace

**Status: draft/proposed, not approved.** Requirements describe candidates to validate, not shipped behavior. No implementation is authorized.

| ID | Proposed requirement | Check before acceptance |
|---|---|---|
| AW-01 | Folder-first identity supports a project without Git; a Git project visibly shows branch and observed worktree information with observation time and unknown/error states. | Fixtures for folder-only, Git, detached, missing and stale snapshot; inspect both states. |
| AW-02 | Project, chat/session, task, run and observed branch/worktree association remain distinct; branch association is not inferred from a chat title. | Model/adapter tests including moved and missing worktrees and same-name projects. |
| AW-03 | Recent sessions can be surfaced first, with a clear pending-answer state that never becomes Done merely because output paused. | Fixture for running, waiting, paused, completed and unknown; inspect ordering and labels. Default landing view remains a founder decision. |
| AW-04 | Provider adapters expose only verified supported operations and capabilities; unavailable/unknown operations fall back to a manual handoff. Provider authentication, permissions and approvals are preserved. | Per-provider documented-interface spike and observed proof for read, open, resume and status separately; unsupported paths fail closed. |
| AW-05 | Only explicitly selected project context and captures are presented for review before a handoff; note text is data, not authority. Cross-project access and exports require scope and existing approvals. | Cross-project and injection fixtures; inspect proposed payload and denial paths; no secrets in logs. |
| AW-06 | A run is explicitly initiated; per-session notify and any supported resume preference are distinct. No auto-approval or permission escalation; stale grants, wrong branch or changed target stop for user review. | Simulate revoked permission, changed worktree/HEAD and pending approval; verify no silent action. |
| AW-07 | At most one editing agent per project initially; reviews can be concurrent. External Git edits are detected or state reported unknown; no claim of global lock on outside tools. | Concurrent start, cancellation, stale lease, crash and external-edit scenarios; no second local editor starts. |
| AW-08 | Local execution ownership and unique run IDs prevent duplicate execution across retries and iCloud replicas. On crash or ambiguous dispatch, surface unknown and reconcile before retry. | Replay, crash between dispatch/ack and two-device retry tests; verify no automatic second execution. |
| AW-09 | Usage limits or paused sessions are visible and prioritizable where provider evidence supports it; estimates are labeled and unknown remains unknown. Preserve the user's queue order and per-session notify/opt-in resume preference; unknown reset time never causes a retry loop. No promise of exact balance or silent provider switching. | Missing/stale usage and provider-unavailable cases; reorder paused tasks; simulate known and unknown reset times and changed permissions. Verify no invented values and no resume outside the selected session policy. |
| AW-10 | Branch and remote evidence distinguish local recorded refs from live GitHub; Jev and GitHub MCP access are capability- and permission-gated. | Stale/offline fixture; inspect source/timestamps, denied access and no unapproved transmission. |
| AW-11 | Validate the process and release boundary for a new open-source desktop app targeting macOS and Windows, distributed outside the Mac App Store through GitHub. No restriction to GitHub repositories. | Document OS-specific process/permission and release/update trust, existing-data boundaries and unsupported capabilities. Signed feasibility artifacts require later authorization; no app bootstrap or sandbox bypass now. |
| AW-12 | Model, adapter and UI tests cover accessibility, large type, privacy, failure and recovery; no automated merge, deploy or publication. | Independent acceptance checklist and relevant test results; human confirms review flow. |
| AW-13 | Each project has a logical session folder gathering related sessions across supported providers and checkouts, with real branch/worktree evidence retained per session. The user can star/unstar the project folder as a favorite. This does not move transcripts, create branches, merge conversations or alter provider configuration. | Fixtures: two providers and two branches for one project, same-name unrelated projects, unavailable provider and uncertain association. Confirm user-supplied links are preserved, uncertain matches are not silently filed, recent session order is clear and incompleteness is labeled. Favorite survives restart and session completion/pauses; unstar does not remove any session. Persistence/identity contract must be settled before building. |

| AW-14 | Core project folders, favorites, session overview and queue must work on macOS and Windows without requiring Unli Rice, iCloud or studio scripts. Provider capabilities may differ and must be explicit per OS; native Windows versus WSL support is not assumed. | Plan fresh-install, Unicode/case/path identity, credential storage, permissions, provider absence, restart and accessibility acceptance on both OSes. No platform is declared supported from a build on the other. |
| AW-15 | Proposed memory split, pending founder decision: minimal local project notes/guardrails/handoffs plus an optional consented Unli Rice connector. Discovery does not mean connection permission. Show data source, scope, freshness and any configuration changes before setup; preserve manual bridges and explicit authority. | Verify useful standalone behavior with no Unli Rice, absent/revoked connector, Windows transport unavailable, conflicting identities and changed guardrails. No silent corpus import, secret transfer or second writable copy of a connected note; reversible disconnect. Full Unli Rice migration/feature transplant excluded unless separately approved. |
| AW-16 | Public open-source code and GitHub releases must have an explicit license/dependency policy, clean sample data, documented builds and per-OS release/update trust design. Open source does not authorize publishing this repo or bundling provider binaries/accounts. | Review current MIT attribution for any reuse, new-license choice, dependencies and provider redistribution limits; verify no personal notes, transcripts, credentials or machine paths in release fixtures. Actual publishing/signing occurs only under future authorization. |
